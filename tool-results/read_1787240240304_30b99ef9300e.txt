    11→## Data Quality State Definitions
    12→
    13→| State | Definition | Disclosure Required |
    14→|-------|-----------|-------------------|
    15→| REAL | Data from a verified external source or honestly computed from real inputs | Source attribution preferred |
    16→| PROXY | Approximation of real data — plausible but not directly sourced | Must label as estimate/approximation |
    17→| DERIVED | Real data transformed by a legitimate, disclosed computation | Method must be documented |
    18→| MISSING | Data that should exist but doesn't — no value shown | Must show honest empty state |
    19→| STALE | Data that was once real but has expired its freshness window | Must show timestamp and age warning |
    20→| UNAVAILABLE | Data that cannot be obtained — honestly disclosed to user | Must explain why unavailable |
    21→| DEMO | Fictional data clearly labeled as sample/demo content | Must have visible DEMO badge/label |
    22→| FABRICATED | **[8th state — added this audit]** Synthetic data presented as real without disclosure. Semantically distinct from DEMO: DEMO implies the user knows it's fictional; FABRICATED means the user is led to believe it's real. This state exists because the Phase 6 data-quality contract's original 7-state schema had no category for "undisclosed fake data masquerading as real" — which is the core trust violation this audit was designed to find. | Must be eliminated or reclassified to DEMO with disclosure |
    23→
    24→**Propagation rule:** FABRICATED propagates upward through all transformations. If *any* input to a DERIVED or PROXY computation is FABRICATED, the output inherits FABRICATED state — regardless of whether the computation itself is legitimate. Rationale: a real method applied to fake inputs produces fake outputs (garbage in, garbage out). The "highest violation" state always wins. This rule applies retroactively to all 9 views in this audit.
