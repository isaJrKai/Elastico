   156→   255→## Table Styles
   157→   256→
   158→   257→**Profile routing:** Profile A (Formal: report, academic, contract, exam) → Three-Line Table or Horizontal-Only Table. Profile B (Visual: resume, copywriting) → Zebra Stripe (preferred) or Horizontal-Only Table.
   159→   258→
   160→   259→### 1. Three-Line Table (三线表) — Academic
   161→   260→
   162→   261→Only three horizontal lines: top of table, bottom of header, bottom of table.
   163→   262→
   164→   263→```js
   165→   264→const threeLineTable = new Table({
   166→   265→  width: { size: 100, type: WidthType.PERCENTAGE },
   167→   266→  borders: {
   168→   267→    top: { style: BorderStyle.SINGLE, size: 4, color: "000000" },
   169→   268→    bottom: { style: BorderStyle.SINGLE, size: 4, color: "000000" },
   170→   269→    left: { style: BorderStyle.NONE },
   171→   270→    right: { style: BorderStyle.NONE },
   172→   271→    insideHorizontal: { style: BorderStyle.NONE },
   173→   272→    insideVertical: { style: BorderStyle.NONE },
   174→   273→  },
   175→   274→  rows: [
   176→   275→    new TableRow({
   177→   276→      children: headerCells.map(text => new TableCell({
   178→   277→        children: [new Paragraph({ children: [new TextRun({ text, bold: true, size: 21 })] })],
   179→   278→        borders: {
   180→   279→          bottom: { style: BorderStyle.SINGLE, size: 2, color: "000000" },
   181→   280→          top: { style: BorderStyle.NONE },
   182→   281→          left: { style: BorderStyle.NONE },
   183→   282→          right: { style: BorderStyle.NONE },
   184→   283→        },
   185→   284→        margins: { top: 60, bottom: 60, left: 120, right: 120 },
   186→   285→      })),
   187→   286→    }),
   188→   287→    // ... data rows with all borders NONE
   189→   288→  ],
   190→   289→});
   191→   290→```
   192→   291→
   193→   292→### 2. Zebra Stripe — Data Reports
   194→   293→
   195→   294→```js
   196→   295→function zebraRow(cells, index, palette) {
   197→   296→  return new TableRow({
   198→   297→    children: cells.map(text => new TableCell({
   199→   298→      children: [new Paragraph({ children: [new TextRun({ text, size: 21 })] })],
   200→   299→      shading: index % 2 === 0
   201→   300→        ? { type: ShadingType.CLEAR, fill: palette.surface }
   202→   301→        : { type: ShadingType.CLEAR, fill: "FFFFFF" },
   203→   302→      margins: { top: 60, bottom: 60, left: 120, right: 120 },
   204→   303→    })),
   205→   304→  });
   206→   305→}
   207→   306→```
   208→   307→
   209→   308→### 3. Horizontal-Only — Business (Default)
   210→   309→
   211→   310→```js
   212→   311→const horizontalTable = new Table({
   213→   312→  width: { size: 100, type: WidthType.PERCENTAGE },
   214→   313→  borders: {
   215→   314→    top: { style: BorderStyle.SINGLE, size: 2, color: palette.accent.replace("#","") },
   216→   315→    bottom: { style: BorderStyle.SINGLE, size: 2, color: palette.accent.replace("#","") },
   217→   316→    left: { style: BorderStyle.NONE },
   218→   317→    right: { style: BorderStyle.NONE },
   219→   318→    insideHorizontal: { style: BorderStyle.SINGLE, size: 1, color: "D0D0D0" },
   220→   319→    insideVertical: { style: BorderStyle.NONE },
   221→   320→  },
   222→   321→  rows: [/* header row with accent shading, then data rows */],
   223→   322→});
   224→   323→```
   225→   324→
   226→   325→**⚠️ CRITICAL**: Always set `margins` at the Table or TableCell level. Without margins, text touches cell borders.
   227→   326→
   228→   327→### Table Color Token Derivation
   229→   328→
   230→   329→Each palette in `coverPalettes` provides a `table` object with pre-computed colors for all 3 table styles:
   231→   330→
   232→   331→| Token | Used in | Description |
   233→   332→|-------|---------|-------------|
   234→   333→| `table.headerBg` | Zebra Stripe, Horizontal-Only | Table header background color |
   235→   334→| `table.headerText` | Zebra Stripe, Horizontal-Only | Table header text color (must pass WCAG AA contrast) |
   236→   335→| `table.accentLine` | Three-Line | Top/bottom/header-bottom line color |
   237→   336→| `table.innerLine` | Horizontal-Only | Inner horizontal separator line color |
   238→   337→| `table.surface` | Zebra Stripe | Alternating row background (light tint) |
   239→   338→
   240→   339→**Usage:**
   241→   340→```js
   242→   341→const palette = coverPalettes["DS-1"];
   243→   342→const t = palette.table;
   244→   343→// Three-Line: use t.accentLine for border colors
   245→   344→// Zebra: use t.headerBg, t.headerText, t.surface
   246→   345→// Horizontal: use t.headerBg, t.headerText, t.innerLine
   247→   346→```
   248→   347→
   249→   348→**⚠️ High-saturation accent override**: For DM-1, FG-1, and SN-2, the table colors are intentionally darkened/desaturated relative to the cover accent. Bright accent colors that look good on dark cover backgrounds are too eye-straining on white body pages. Always use `palette.table.*` for tables, never the raw `palette.accent`.

   254→   353→## Cover Page Design System
   255→   354→
   256→   355→### Design Philosophy
   257→   356→
   258→   357→Covers use **7 validated layout recipes** + **parameterized variants** instead of free combination. Each recipe's background, layout, and decoration are visually verified. Differentiation comes from **palette × font size × content variation**.
   259→   358→
   260→   359→**Architecture principle:** All recipes use a **single 16838 outer wrapper table** (one row, exact height). Recipes R1/R2/R3 use **ZERO nested tables** — all decoration is achieved via **paragraph borders** (left/right/top/bottom). This ensures maximum cross-engine stability (MS Office + WPS).
   261→   360→
   262→   361→### Cover Color Palettes (Dark Mode + Light Mode)
   263→   362→
   264→   363→Each palette defines 3 core colors (Background, Primary, Accent) + derived cover/table tokens.
   265→   364→
   266→   365→⚠️ **Disambiguation: `cover.titleColor` is a COLOR value, not title text.** All keys under `cover: { ... }` are **color hex codes** for styling cover text elements.    267→   366→
   268→   367→```js
   269→   368→// ✅ Correct — config.title is the text, P.titleColor is the color
   270→   369→new TextRun({ text: config.title, color: P.titleColor })
   271→   370→
   272→   371→// ❌ WRONG — using color value as text content
   273→   372→new TextRun({ text: P.titleColor, color: P.titleColor })  // displays "FFFFFF" as visible text!
   274→   373→```

   402→   501→### ⚠️ Recipe Routing Rules (Replaces Free Selection)
   403→   502→
   404→   503→```js
   405→   504→function selectCoverRecipe(docType, industry, titleLength) {
   406→   505→  // No cover for these types
   407→   506→  if (["contract", "official", "exam", "resume"].includes(docType)) return null;
   408→   507→
   409→   508→  // Academic
   410→   509→  if (docType === "academic") return { recipe: "R5", palette: "ACADEMIC" };
   411→   510→
   412→   511→  // Thesis proposal report (开题报告)
   413→   512→  if (docType === "proposal_report") return { recipe: "R5", palette: "ACADEMIC" };
   414→   513→
   415→   514→  // Lesson plans — R6 editorial for arts/general, R4 for STEM
   416→   515→  if (docType === "lesson_plan" || docType === "lessonplan") {
   417→   516→    const stemKeywords = ["math", "physics", "chemistry", "biology", "science", "tech", "computer", "engineering"];
   418→   517→    if (stemKeywords.some(k => (industry || "").toLowerCase().includes(k))) {
   419→   518→      return { recipe: "R4", palette: "DM-1" };
   420→   519→    }
   421→   520→    // Arts, general, and all other lesson plans → R6 editorial
   422→   521→    return { recipe: "R6", palette: "ED-1" };
   423→   522→  }
   424→   523→
   425→   524→  // Creative/branding/design (formal) → R3 centered card frame
   426→   525→  if (["creative", "branding", "design"].includes(docType)) {
   427→   526→    return { recipe: "R3", palette: "SN-2" };
   428→   527→  }
   429→   528→
   430→   529→  // Cultural/newsletter/internal (casual) → R6 editorial
   431→   530→  if (["cultural", "newsletter", "internal"].includes(docType)) {
   432→   531→    return { recipe: "R6", palette: "ED-1" };
   433→   532→  }
   434→   533→
   435→   534→  // Activity/event planning → R6 editorial
   436→   535→  if (docType === "activity") return { recipe: "R6", palette: "ED-1" };
   437→   536→
   438→   537→  // Trend/research reports in cultural/creative/brand fields → R7 Swiss Tech
   439→   538→  if (docType === "trend_report" || docType === "research_report") {
   440→   539→    if (["cultural", "creative", "brand", "design"].includes(industry)) {
   441→   540→      return { recipe: "R7", palette: "ST-1" };
   442→   541→    }
   443→   542→  }
   444→   543→
   445→   544→  // Formal/business subtypes
   446→   545→  if (docType === "whitepaper") return { recipe: "R2", palette: industry === "finance" ? "IG-1" : "CM-2" };
   447→   546→  if (docType === "consulting") return { recipe: "R2", palette: "MIN-1" };
   448→   547→  if (docType === "proposal" || docType === "plan") return { recipe: "R4", palette: "GO-1" };
   449→   548→
   450→   549→  // Reports — palette by industry, use R1
   451→   550→  if (docType === "report") {
   452→   551→    const paletteMap = {
   453→   552→      finance: "IG-1", consulting: "MIN-1",
   454→   553→      tech: "DM-1", ai: "DM-1",
   455→   554→      education: "WM-1", green: "FG-1",
   456→   555→      medical: "MC-1", government: "GV-1",
   457→   556→    };
   458→   557→    return { recipe: "R1", palette: paletteMap[industry] || "DS-1" };
   459→   558→  }
   460→   559→
   461→   560→  // Default
   462→   561→  return { recipe: "R1", palette: "DS-1" };
   463→   562→}
   464→   563→
   465→   564→// ── Long-title override (applied AFTER initial recipe selection) ──
   466→   565→// Call this after selectCoverRecipe() when the actual title text is known.
   467→   566→function applyLongTitleOverride(result, titleLength) {
   468→   567→  if (!result || !result.recipe) return result;
   469→   568→  // R5 (academic) is never overridden — it has its own calcTitleLayoutMixed()
   470→   569→  if (result.recipe === "R5") return result;
   471→   570→  // R6 (editorial) is designed for short titles only (≤20 chars, single line)
   472→   571→  // Long titles → fall back to R1 (handles long titles best)
   473→   572→  if (titleLength > 20 && result.recipe === "R6") {
   474→   573→    return { recipe: "R1", palette: "WM-1" }; // ED-1 has no dark bg, use WM-1 (warm teal)
   475→   574→  }
   476→   575→  // R3/R4 struggle with long titles → fall back to R1 (same palette)
   477→   576→  if (titleLength > 20 && ["R3", "R4"].includes(result.recipe)) {
   478→   577→    return { recipe: "R1", palette: result.palette };
   479→   578→  }
   480→   579→  // Very long titles: even R2 centered looks scattered → R1 left-aligned
   481→   580→  if (titleLength > 30 && result.recipe === "R2") {
   482→   581→    return { recipe: "R1", palette: result.palette };
   483→   582→  }
   484→   583→  return result;
   485→   584→}

   547→   646→
   548→   647→### ⚠️ Cover Content Overflow Prevention (Mandatory)
   549→   648→
   550→   649→1. Cover section page margin is 0; total content height ≤ 15638 twips (1200 twips safety margin for cross-engine compatibility — MS Office renders large fonts taller than calculated).
   551→   650→2. Color block Table `height` must use `rule: "exact"` (never `"atLeast"`).
   552→   651→3. Each recipe code includes height budget annotations — verify during generation.
   553→   652→4. **`verticalAlign` must always be `"top"`**. Never use `"center"` or `"bottom"` in exact-height rows — content will be clipped or overflow. Use `spacing.before` on the first paragraph for vertical positioning.
   554→   653→5. **Title font size MUST be dynamically calculated via `calcTitleLayout()`** (see below). Never hardcode font sizes above 40pt for cover titles. Every recipe MUST call `calcTitleLayout()` before building title paragraphs.
   555→   654→6. **Never use `margins.top`/`margins.bottom` for vertical positioning inside exact-height cells**: Cell margins reduce available height unpredictably across MS Office and WPS. Use `spacing.before` on the first paragraph instead. Only `margins.left`/`margins.right` are safe.
   556→   655→7. **Dynamic spacing is mandatory**: Use `calcCoverSpacing()` to compute `spacing.before` values dynamically based on content element count and title line count. Never use fixed large spacing values (e.g., `before: 4500`) that assume a specific title length.
   557→   656→8. **Cover must be a single-page section**: The cover section must produce exactly ONE page. If content overflows to a second page, it means the height budget is violated. Common overflow causes and fixes:
   558→   657→   - Title font too large → use `calcTitleLayout()` to auto-reduce
   559→   658→   - Too many meta lines → reduce font size or remove less important lines
   560→   659→   - Fixed `spacing.before` values too large → use `calcCoverSpacing()` for dynamic values
   561→   660→   - Subtitle + English label + meta lines combined exceed budget → calculate total and reduce spacing
   562→   661→9. **Cover wrapper table MUST use explicit `allNoBorders`**: The outer 16838 wrapper table and ALL nested tables inside the cover MUST set borders to NONE explicitly. Never rely on docx-js default borders (`single/auto/sz=4`). Default borders add ~8 twips per edge, which causes MS Office to calculate a total height slightly exceeding 16838 → content overflows to a blank page 2. WPS is more lenient but MS Office is strict. **This is the #1 cause of "blank page 2 in MS Office but not in WPS".**
   563→   662→
   564→   663→```js
   565→   664→// ✅ MANDATORY: Define and use allNoBorders for every cover table
   566→   665→const NB = { style: BorderStyle.NONE, size: 0, color: "FFFFFF" };
   567→   666→const noBorders = { top: NB, bottom: NB, left: NB, right: NB };
   568→   667→const allNoBorders = { top: NB, bottom: NB, left: NB, right: NB,
   569→   668→                       insideHorizontal: NB, insideVertical: NB };
   570→   669→
   571→   670→new Table({
   572→   671→  borders: allNoBorders,  // ← MANDATORY on every cover table
   573→   672→  // ...
   574→   673→});
   575→   674→```
   576→   675→
   577→   676→10. **Decorative lines MUST use paragraph borders, NEVER text characters**: Horizontal decorative lines (accent strips, dividers, frame edges) must be implemented with `paragraph border.top` or `border.bottom` — never with text characters like `───`, `━━━`, `═══`, or `——————`. Character-drawn lines render at inconsistent widths across MS Office and WPS (font metrics differ), causing lines to appear truncated or misaligned. Paragraph borders render pixel-perfect in both engines and their width is controlled precisely via `indent.left` / `indent.right`.
   578→   677→
   579→   678→```js
   580→   679→// ✅ Correct — paragraph border (R2 style thick accent rule)
   581→   680→new Paragraph({
   582→   681→  indent: { left: 1000, right: 1000 },
   583→   682→  border: { top: { style: BorderStyle.SINGLE, size: 18, color: P.accent, space: 20 } },
   584→   683→  children: [],
   585→   684→})
   586→   685→
   587→   686→// ❌ FORBIDDEN — text character line (renders inconsistently)
   588→   687→new Paragraph({
   589→   688→  children: [new TextRun({ text: "───────────────", color: P.accent })]
   590→   689→})
   591→   690→```
   592→   691→9. **Post-generation overflow check (mandatory)**: After building cover children, estimate total height:
   593→   692→   ```js
   594→   693→   function estimateCoverHeight(elements) {
   595→   694→     let total = 0;
   596→   695→     for (const el of elements) {
   597→   696→       if (el instanceof Table) {
   598→   697→         // Sum row heights (exact rows) or estimate 400 twips per row
   599→   698→         const rows = el.root?.[0]?.rows || [];
   600→   699→         for (const row of rows) {
   601→   700→           total += row.height?.value || 400;
   602→   701→         }
   603→   702→       } else if (el instanceof Paragraph) {
   604→   703→         const fontSize = el.root?.[0]?.size || 24; // half-pts
   605→   704→         // ★ Use pt * 11.5 (= half-pt * 10 * 1.15) for accurate single-spacing estimate
   606→   705→         const lineHeight = Math.max(fontSize * 11.5, 276); // min 276 (default 12pt)
   607→   706→         const spacingBefore = el.spacing?.before || 0;
   608→   707→         const spacingAfter = el.spacing?.after || 0;
   609→   708→         total += lineHeight + spacingBefore + spacingAfter;
   610→   709→       }
   611→   710→     }
   612→   711→     return total;
   613→   712→   }
   614→   713→   // ★ Target: estimateCoverHeight(coverChildren) < 15638 (16838 - 1200 safety)
   615→   714→   ```

   619→   718→### ⚠️ Cover Title Layout — calcTitleLayout() (Mandatory for ALL Recipes)
   620→   719→
   621→   720→**Every cover recipe MUST use `calcTitleLayout()` to determine title font size and line breaks.** Hardcoding font sizes or passing the full title as a single TextRun is FORBIDDEN.
   622→   721→
   623→   722→**Every paragraph with font size > body text MUST set explicit line spacing** to prevent top clipping:
   624→   723→```js
   625→   724→// ★ MANDATORY: prevent inherited small line spacing from clipping large fonts
   626→   725→spacing: { line: Math.ceil(titlePt * 23), lineRule: "atLeast", after: 100 }
   627→   726→// Example: 36pt → line: 828; 44pt → line: 1012
   628→   727→```
   629→   728→Without this, the paragraph inherits body text line spacing (e.g., 560tw), which is shorter than the font height → top of characters gets clipped.
   630→   729→
   631→   730→```js
   632→   731→/**
   633→   732→ * Calculate safe font size and smart line breaks for cover titles.
   634→   733→ * MUST be called by every recipe before building title paragraphs.
   635→   734→ *
   636→   735→ * @param {string}  title          Full title string
   637→   736→ * @param {number}  maxWidthTwips  Available width for title text (twips, after subtracting margins/padding)
   638→   737→ * @param {number}  preferredPt    Desired max font size in pt (default 40)
   639→   738→ * @param {number}  minPt          Minimum allowed font size in pt (default 24)
   640→   739→ * @returns {{ titlePt: number, titleLines: string[] }}
   641→   740→ */
   642→   741→function calcTitleLayout(title, maxWidthTwips, preferredPt = 40, minPt = 24) {
   643→   742→  // Each CJK character width ≈ pt × 20 twips
   644→   743→  const charWidth = (pt) => pt * 20;
   645→   744→  const charsPerLine = (pt) => Math.floor(maxWidthTwips / charWidth(pt));
   646→   745→
   647→   746→  // Try from preferredPt downward until title fits in ≤ 3 lines
   648→   747→  let titlePt = preferredPt;
   649→   748→  let lines;
   650→   749→  while (titlePt >= minPt) {
   651→   750→    const cpl = charsPerLine(titlePt);
   652→   751→    if (cpl < 2) { titlePt -= 2; continue; }
   653→   752→    lines = splitTitleLines(title, cpl);
   654→   753→    if (lines.length <= 3) break;
   655→   754→    titlePt -= 2;
   656→   755→  }
   657→   756→
   658→   757→  // If still > 3 lines at minPt, force 3 lines
   659→   758→  if (!lines || lines.length > 3) {
   660→   759→    const cpl = charsPerLine(minPt);
   661→   760→    lines = splitTitleLines(title, cpl);
   662→   761→    titlePt = minPt;
   663→   762→  }
   664→   763→
   665→   764→  return { titlePt, titleLines: lines };
   666→   765→}
   667→   766→
   668→   767→/**
   669→   768→ * Smart Chinese title line-breaking — breaks at semantic boundaries, never mid-word.
   670→   769→ *
   671→   770→ * Rules:
   672→   771→ * 1. Prefer breaking after particles, punctuation, connectors, underscores, spaces
   673→   772→ * 2. Never split a compound word (e.g., "管理规范" must not become "管理规" + "范")
   674→   773→ * 3. No single-character orphan on the last line — merge into previous line
   675→   774→ * 4. If no good break point found within 60-130% of charsPerLine, break at charsPerLine
   676→   775→ *
   677→   776→ * @param {string} title        Full title string
   678→   777→ * @param {number} charsPerLine Max characters per line at current font size
   679→   778→ * @returns {string[]}          Array of line strings
   680→   779→ */
   681→   780→function splitTitleLines(title, charsPerLine) {
   682→   781→  if (title.length <= charsPerLine) return [title];
   683→   782→
   684→   783→  // Characters that are safe break points (break AFTER these)
   685→   784→  const breakAfter = new Set([
   686→   785→    ...'，。、；：！？',              // CJK punctuation
   687→   786→    ...'的与和及之在于为',            // CJK particles/prepositions
   688→   787→    ...'-_—–·/',                     // connectors
   689→   788→    ...' \t',                         // whitespace
   690→   789→  ]);
   691→   790→
   692→   791→  const lines = [];
   693→   792→  let remaining = title;
   694→   793→
   695→   794→  while (remaining.length > charsPerLine) {
   696→   795→    let breakAt = -1;
   697→   796→
   698→   797→    // Search backward from charsPerLine to 60% for a break point
   699→   798→    for (let i = charsPerLine; i >= Math.floor(charsPerLine * 0.6); i--) {
   700→   799→      if (i < remaining.length && breakAfter.has(remaining[i - 1])) {
   701→   800→        breakAt = i;
   702→   801→        break;
   703→   802→      }
   704→   803→    }
   705→   804→
   706→   805→    // If not found, search forward up to 130%
   707→   806→    if (breakAt === -1) {
   708→   807→      const limit = Math.min(remaining.length, Math.ceil(charsPerLine * 1.3));
   709→   808→      for (let i = charsPerLine + 1; i < limit; i++) {
   710→   809→        if (breakAfter.has(remaining[i - 1])) {
   711→   810→          breakAt = i;
   712→   811→          break;
   713→   812→        }
   714→   813→      }
   715→   814→    }
   716→   815→
   717→   816→    // Last resort: break at charsPerLine, but avoid splitting compound CJK words
   718→   817→    if (breakAt === -1) {
   719→   818→      breakAt = charsPerLine;
   720→   819→      // If both chars at the break boundary are CJK (likely a compound word),
   721→   820→      // step back 1 char to keep the word together
   722→   821→      const prevChar = remaining[breakAt - 1];
   723→   822→      const nextChar = remaining[breakAt];
   724→   823→      if (prevChar && nextChar &&
   725→   824→          !breakAfter.has(prevChar) && !breakAfter.has(nextChar) &&
   726→   825→          /[\u4e00-\u9fff]/.test(prevChar) && /[\u4e00-\u9fff]/.test(nextChar)) {
   727→   826→        breakAt = breakAt - 1;
   728→   827→      }
   729→   828→    }
   730→   829→
   731→   830→    lines.push(remaining.slice(0, breakAt).trim());
   732→   831→    remaining = remaining.slice(breakAt).trim();
   733→   832→  }
   734→   833→  if (remaining) lines.push(remaining);
   735→   834→
   736→   835→  // Prevent single-character orphan on last line — merge into previous
   737→   836→  if (lines.length > 1 && lines[lines.length - 1].length <= 2) {
   738→   837→    const last = lines.pop();
   739→   838→    lines[lines.length - 1] += last;
   740→   839→  }
   741→   840→
   742→   841→  return lines;
   743→   842→}
   744→   843→
   745→   844→/**
   746→   845→ * Calculate dynamic spacing values for cover elements to fit within page height.
   747→   846→ *
   748→   847→ * @param {object} params
   749→   848→ * @param {number} params.titleLineCount   Number of title lines
   750→   849→ * @param {number} params.titlePt          Title font size in pt
   751→   850→ * @param {boolean} params.hasSubtitle     Whether subtitle exists
   752→   851→ * @param {boolean} params.hasEnglishLabel Whether English label exists
   753→   852→ * @param {number} params.metaLineCount    Number of meta info lines
   754→   853→ * @param {number} params.fixedHeight      Sum of fixed-height elements (color strips, accent bars, footer) in twips
   755→   854→ * @param {number} params.pageHeight       Total page height in twips (default 16838)
   756→   855→ * @returns {{ topSpacing, midSpacing, bottomSpacing }}  Spacing values in twips
   757→   856→ */
   758→   857→function calcCoverSpacing(params) {
   759→   858→  const {
   760→   859→    titleLineCount = 1, titlePt = 36, hasSubtitle = false,
   761→   860→    hasEnglishLabel = false, metaLineCount = 0,
   762→   861→    fixedHeight = 800, pageHeight = 16838,
   763→   862→    marginTop = 0, marginBottom = 0,   // ★ NEW: pass actual section margins
   764→   863→  } = params;
   765→   864→
   766→   865→  // ★ Safety margin: 1200 twips (cross-engine: MS Office renders large fonts
   767→   866→  // taller than calculated; extra 400tw buffer prevents footer clipping)
   768→   867→  const SAFETY = 1200;
   769→   868→  // ★ Subtract page margins from available height (cover section may have margins)
   770→   869→  const usableHeight = pageHeight - marginTop - marginBottom - SAFETY;
   771→   870→
   772→   871→  // ★ Accurate height estimation per element:
   773→   872→  const titleHeight = titleLineCount * (titlePt * 23 + 200);
   774→   873→  const subtitleHeight = hasSubtitle ? (12 * 23 + 600) : 0;
   775→   874→  const englishLabelHeight = hasEnglishLabel ? (9 * 23 + 600) : 0;
   776→   875→  const metaHeight = metaLineCount * (10 * 23 + 100);
   777→   876→
   778→   877→  // ★ Account for implicit paragraph heights:
   779→   878→  const implicitParaHeight = 3 * 300;
   780→   879→
   781→   880→  const contentHeight = titleHeight + subtitleHeight + englishLabelHeight +
   782→   881→                        metaHeight + fixedHeight + implicitParaHeight;
   783→   882→
   784→   883→  const remainingSpace = usableHeight - contentHeight;
   785→   884→  const safeRemaining = Math.max(remainingSpace, 400);
   786→   885→
   787→   886→  // ★ Footer protection: bottomSpacing must be ≥ FOOTER_MIN to prevent
   788→   887→  // footer + accent line from being clipped at the cell bottom edge
   789→   888→  const FOOTER_MIN = 800;
   790→   889→  const rawTop = Math.floor(safeRemaining * 0.45);
   791→   890→  const rawBottom = Math.floor(safeRemaining * 0.45);
   792→   891→  const bottomSpacing = Math.max(rawBottom, FOOTER_MIN);
   793→   892→  const topSpacing = Math.max(rawTop - Math.max(0, FOOTER_MIN - rawBottom), 400);
   794→   893→  const midSpacing = Math.max(safeRemaining - topSpacing - bottomSpacing, 0);
   795→   894→
   796→   895→  return { topSpacing, midSpacing, bottomSpacing };
   797→   896→}
   798→   897→```
   799→   898→
   800→   899→**Usage in every recipe:**
   801→   900→```js

   805→   904→const titleSize = titlePt * 2; // convert to half-points for docx-js
   806→   905→
   807→   906→// Step 2: Calculate spacing (pass actual section margins!)

   809→   908→  titleLineCount: titleLines.length,
   810→   909→  titlePt,
   811→   910→  hasSubtitle: !!config.subtitle,
   812→   911→  hasEnglishLabel: !!config.englishLabel,
   813→   912→  metaLineCount: (config.metaLines || []).length,
   814→   913→  fixedHeight: 800, // sum of accent strips, footer table, etc.
   815→   914→  marginTop: 0,     // ★ pass the cover section's actual top margin (twips)
   816→   915→  marginBottom: 0,  // ★ pass the cover section's actual bottom margin (twips)
   817→   916→});
   818→   917→
   819→   918→// Step 3: Use in paragraphs

   821→   920→// ... title paragraphs using titleLines and titleSize ...

   827→   926→### ⚠️ CRITICAL — Cover Section Non-Negotiables (ALL Recipes)
   828→   927→
   829→   928→These 3 properties are MANDATORY for every cover implementation (R1–R7). Omitting ANY of them causes cover layout failure:
   830→   929→
   831→   930→1. **Cover section margin = 0**: The cover MUST be in its own section with `page.margin: { top: 0, bottom: 0, left: 0, right: 0 }`. Non-zero margins shrink the wrapper away from page edges → white gaps around the cover ("cover not filling the page"). This is the #1 cause of broken cover layouts.
   832→   931→
   833→   932→2. **Wrapper row exact height**: The outer wrapper table row MUST set `height: { value: 16838, rule: "exact" }`. Without this, content overflow pushes to page 2, or insufficient content leaves bottom whitespace.
   834→   933→
   835→   934→3. **Wrapper table borders = allNoBorders**: MUST explicitly set `borders: allNoBorders`. Default docx-js borders add ~8 twips per edge. MS Office includes border thickness in exact-height calculation → total exceeds 16838 → blank page 2 (WPS is lenient, MS Office is strict).
   836→   935→
   837→   936→**Cover section template (copy this for every Recipe):**
   838→   937→```js
   839→   938→sections: [
   840→   939→  {
   841→   940→    // ⚠️ Cover section — margin MUST be 0, separate from body
   842→   941→    properties: {
   843→   942→      page: {
   844→   943→        size: { width: 11906, height: 16838 },
   845→   944→        margin: { top: 0, bottom: 0, left: 0, right: 0 },
   846→   945→      },
   847→   946→    },
   848→   947→    children: buildCoverRX(config), // ← replace with actual recipe function
   849→   948→  },
   850→   949→  {
   851→   950→    // Body section — normal margins
   852→   951→    properties: {
   853→   952→      type: SectionType.NEXT_PAGE,
   854→   953→      page: {
   855→   954→        size: { width: 11906, height: 16838 },
   856→   955→        margin: { top: 1440, bottom: 1440, left: 1701, right: 1417 },
   857→   956→      },

   860→   959→  },

  1346→  1445→### Recipe R5: Clean White (Academic)
  1347→  1446→
  1348→  1447→**Visual:** Pure white background + school name + centered title + 2-column meta info table with underlines + footer
  1349→  1448→**Use case:** academic thesis, standards documents
  1350→  1449→**Architecture:** 16838 outer wrapper (white fill, invisible) + cell margins for page margin simulation. No top/bottom decorative lines.
  1351→  1450→
  1352→  1451→**Meta info table rules (cross-engine safe):**
  1353→  1452→- 2-column table: label + value, **percentage widths only** (`WidthType.PERCENTAGE`)
  1354→  1453→- **Table width is adaptive:** 55–75% of page, calculated by `calcR5MetaLayout()`. Table centered via `alignment: CENTER`.
  1355→  1454→- **Label column:** adaptive 25–45% of table, **LEFT aligned**, plain text with "：" appended. NO full-width space padding, NO right-alignment.
  1356→  1455→- **Label column borders:** none (no bottom border on label cells).
  1357→  1456→- **Value column:** remaining %, **LEFT aligned**, `bottom: single sz=4` border = fixed-length underline (consistent length for all rows regardless of text).
  1358→  1457→- No left/right/top borders on either column.
  1359→  1458→- ⚠️ Do NOT use DXA widths, full-width space padding (`\u3000`), spacer columns, or tab stops — WPS renders them inconsistently.
  1360→  1459→- ⚠️ Do NOT use `margins.top` on the wrapper cell — use `spacing.before` on first paragraph instead.
  1361→  1460→
  1362→  1461→**Known limitation:** When meta lines ≥ 6 AND title has 3 lines, MS Office may render content slightly taller than WPS, potentially clipping the footer line. Mitigate by reducing `midSpacing` or using a smaller title font.
  1363→  1462→
  1364→  1463→```js
  1365→  1464→// ── Width-aware title layout (handles mixed Chinese + English) ──
  1366→  1465→function estimateTextWidth(text, pt) {
  1367→  1466→  let width = 0;
  1368→  1467→  for (const ch of text) {
  1369→  1468→    const code = ch.codePointAt(0);
  1370→  1469→    const isCJK = (code >= 0x4E00 && code <= 0x9FFF) || (code >= 0x3400 && code <= 0x4DBF) ||
  1371→  1470→      (code >= 0x3000 && code <= 0x303F) || (code >= 0xFF00 && code <= 0xFFEF) ||
  1372→  1471→      (code >= 0x2E80 && code <= 0x2EFF);
  1373→  1472→    width += isCJK ? pt * 20 : pt * 11; // CJK: full-width, Latin: ~55% width
  1374→  1473→  }
  1375→  1474→  return width;
  1376→  1475→}
  1377→  1476→// Use estimateTextWidth() in calcTitleLayout() instead of simple char count
  1378→  1477→// to prevent mid-word breaks in mixed Chinese+English titles like "基于Transformer架构的..."
  1379→  1478→
  1380→  1479→// ── Meta info table ──
  1381→  1480→
  1382→  1481→// Calculate adaptive table and label column percentage based on longest label.
  1383→  1482→// Returns { tablePct, labelPct } — both as percentages.
  1384→  1483→// Uses ONLY WidthType.PERCENTAGE for cross-engine compatibility (MS Office + WPS).
  1385→  1484→function calcR5MetaLayout(metaEntries, fontPt = 12) {
  1386→  1485→  const maxLabelLen = Math.max(...metaEntries.map(e => [...e.label].length));
  1387→  1486→  // Label needs: maxLabelLen chars + "：" + 1 char padding
  1388→  1487→  const labelNeedTw = (maxLabelLen + 2) * fontPt * 20;
  1389→  1488→  // Value column: fixed ~5000tw for consistent underline length
  1390→  1489→  const valueNeedTw = 5000;
  1391→  1490→  const totalNeedTw = labelNeedTw + valueNeedTw;
  1392→  1491→  // Table width as % of page (11906tw), clamped to 55–75%
  1393→  1492→  const tablePct = Math.min(75, Math.max(55, Math.ceil(totalNeedTw / 11906 * 100)));
  1394→  1493→  // Label % within the table, clamped to 25–45%
  1395→  1494→  const rawLabelPct = Math.ceil(labelNeedTw / (tablePct / 100 * 11906) * 100);
  1396→  1495→  return { tablePct, labelPct: Math.max(25, Math.min(45, rawLabelPct)) };
  1397→  1496→}

  1399→  1498→// Build R5 academic cover meta info table.
  1400→  1499→// ⚠️ CRITICAL cross-engine rules:
  1401→  1500→//   - Table width: WidthType.PERCENTAGE (NOT DXA — WPS breaks with DXA)
  1402→  1501→//   - Column widths: WidthType.PERCENTAGE
  1403→  1502→//   - Label column: LEFT aligned, plain text (NO full-width space padding)
  1404→  1503→//   - Value column: LEFT aligned, bottom border = fixed-length underline
  1405→  1504→//   - Table alignment: CENTER (visually centered on page)
  1406→  1505→function buildR5MetaTable(metaEntries) {

  1417→  1516→        borders: noBorders,

  1419→  1518→        children: [new Paragraph({

  1422→  1521→          children: [new TextRun({
  1423→  1522→            text: entry.label + "：",

  1428→  1527→      // Value cell: left-aligned, bottom border = fixed-length underline

  1438→  1537→            size: 24, font: { eastAsia: "SimSun", ascii: "Times New Roman" },

  1561→  1660→function blendColors(hex1, hex2, ratio) {
  1562→  1661→  const p = (s, i) => parseInt(s.replace("#","").slice(i, i+2), 16);
  1563→  1662→  const mix = (c1, c2) => Math.round(c1 + (c2 - c1) * ratio);
  1564→  1663→  const r = mix(p(hex1,0), p(hex2,0)), g = mix(p(hex1,2), p(hex2,2)), b = mix(p(hex1,4), p(hex2,4));
  1565→  1664→  return [r, g, b].map(v => v.toString(16).padStart(2,"0")).join("");
  1566→  1665→}

  1600→  1699→
  1601→  1700→### Chart Color Palette
  1602→  1701→
  1603→  1702→Default: **low-saturation (Morandi style)** palette to avoid flashy high-saturation. High-saturation palette only for explicitly energetic scenarios (events/education/creative).
  1604→  1703→

  1607→  1706→  // Default: low saturation, professional (S: 25-40%, L: 55-68%)
  1608→  1707→  default: ["6B9DAD", "C49B72", "7BA68A", "B87472", "9687A8", "C8B87C", "7AADA0", "7A9BB8"],
  1609→  1708→  // Vivid: only for energetic/creative scenes
  1610→  1709→  vivid:   ["2F97B8", "E67E22", "27AE60", "E74C3C", "9B59B6", "F1C40F", "1ABC9C", "3498DB"],
  1611→  1710→};
  1612→  1711→
  1613→  1712→// Scene selection:
  1614→  1713→// - report/whitepaper/consulting/academic/contract → default
  1615→  1714→// - activity/education/creative copy → vivid (optional)
  1616→  1715→```
  1617→  1716→
  1618→  1717→**Color usage rules:**
  1619→  1718→- Max **5 colors** per chart; excess categories use depth variants of same hue
  1620→  1719→- Emphasis data uses document accent color; non-emphasis uses grey `#B0B0B0`
  1621→  1720→- Adjacent segments in pie/bar charts must have hue gap ≥ 60°
  1622→  1721→
  1623→  1722→1. **Anti-overlap**: If >6 x-axis labels, rotate 45° (`plt.xticks(rotation=45, ha='right')`)
  1624→  1723→2. **Anti-stretch**: Always set figure size explicitly (`fig, ax = plt.subplots(figsize=(10, 6))`)
  1625→  1724→3. **Aspect ratio (CRITICAL)**: When embedding in docx, MUST read actual image dimensions and calculate height proportionally. NEVER hardcode both width and height — pie charts become ellipses, radar charts become diamonds.
  1626→  1725→   ```js
  1627→  1726→   const sizeOf = require("image-size");
  1628→  1727→   const dims = sizeOf(chartBuffer);
  1629→  1728→   const displayWidth = 500;
  1630→  1729→   const displayHeight = Math.round(displayWidth * (dims.height / dims.width));
  1631→  1730→   // transformation: { width: displayWidth, height: displayHeight }
  1632→  1731→   ```
  1633→  1732→4. **DPI**: Save at 200+ DPI (`plt.savefig("chart.png", dpi=200, bbox_inches="tight")`)
  1634→  1733→5. **Colors**: Use palette accent color for primary data series
  1635→  1734→6. **Legend**: Place outside plot area if >4 series
  1636→  1735→7. **Square charts**: Pie and radar charts MUST use `figsize=(8, 8)` (equal width/height) to preserve circular/radial shape
  1637→  1736→7. **Grid**: Light gray grid (`ax.grid(True, alpha=0.3)`)
