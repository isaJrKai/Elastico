    30→
    31→# 1. WHAT ELASTICO IS
    32→
    33→ELASTICO is a **football intelligence workstation**.
    34→
    35→It is not:
    36→
    37→- a generic SaaS dashboard
    38→- an AI chatbot with football colors
    39→- a fantasy football website
    40→- an admin panel
    41→- a collection of cards
    42→- a collection of charts
    43→- an "AI-generated dashboard"
    44→
    45→It should feel like a place where a serious football analyst could spend hours.
    46→
    47→The feeling should be:
    48→
    49→**precise · calm · fast · intelligent · spatial · football-native · premium · purposeful**
    50→
    51→The intelligence should be felt through the quality of the experience rather than repeatedly advertised as "AI".
    52→
    53→---
    54→
    55→# 2. THE ANTI-AI-GENERATED-DESIGN RULE
    56→
    57→AI-generated interfaces often have:
    58→
    59→- cards everywhere
    60→- identical rounded rectangles
    61→- gradients for no reason
    62→- glowing borders
    63→- excessive neon
    64→- giant headings
    65→- too many badges
    66→- random statistics
    67→- charts with no purpose
    68→- icons beside everything
    69→- excessive pills
    70→- "AI Insight" boxes everywhere
    71→- five equally important buttons
    72→- symmetrical layouts everywhere
    73→- fake-looking avatars
    74→- fake-looking logos
    75→- placeholder content
    76→- decorative empty space
    77→- animations without purpose
    78→
    79→**ELASTICO must deliberately avoid this.**
    80→
    81→For every element ask:
    82→
    83→> Why is this here?
    84→> Why is it this size?
    85→> Why is it positioned here?
    86→> Why does it appear before that information?
    87→> What does the user gain from seeing it?
    88→
    89→If there is no strong answer, remove it.
    90→
    91→---
    92→
    93→# 3. DESIGN FOR HUMAN THINKING
    94→
    95→Do not start by asking how many cards a page needs.
    96→
    97→Ask what the user is trying to understand.
    98→
    99→The core ELASTICO cognitive flow is:
   100→
   101→```text
   102→WHERE AM I?
   103→      ↓
   104→WHAT IS HAPPENING?
   105→      ↓
   106→WHAT MATTERS?
   107→      ↓
   108→WHY IS IT HAPPENING?
   109→      ↓
   110→WHAT EVIDENCE SUPPORTS IT?
   111→      ↓
   112→WHAT CAN I DO NEXT?
   113→```
   114→
   115→Every major screen should support this progression.
   116→
   117→---
   118→
   119→# 4. INFORMATION HIERARCHY
   120→
   121→Every screen needs:
   122→
   123→### Orientation
   124→Where am I? What entity? What state? What time/context?
   125→
   126→### Primary information
   127→The single most important thing.
   128→
   129→### Supporting evidence
   130→Metrics, charts, events, tactical information, model factors.
   131→
   132→### Exploration
   133→Secondary information for deeper investigation.
   134→
   135→### Actions
   136→Actions placed where they become useful, not dumped at the top.
   137→
   138→Never make every section visually equal.
   139→
   140→---
   141→
   142→# 5. BUTTON PSYCHOLOGY
   143→
   144→Every screen gets:
   145→
   146→### One primary action
   147→
   148→Then secondary actions.
   149→
   150→Example:
   151→
   152→```text
   153→Arsenal vs Chelsea
   154→
   155→[ Analyse Match ]     ← primary
   156→
   157→Add prediction
   158→Compare teams
   159→Explore tactics
   160→Share
   161→```
   162→
   163→Do not make five buttons equally bright.
   164→
   165→Button labels should describe outcomes:
   166→
   167→- Analyse Match
   168→- Compare Players
   169→- View Full Analysis
   170→- Explore Tactics
   171→- Run Simulation
   172→- Open Prediction
   173→- View Match
   174→
   175→Avoid vague labels such as:
   176→
   177→- Go
   178→- Continue
   179→- Submit
   180→- More
   181→- AI
   182→
   183→Icons should improve recognition, not decorate empty space.
   184→
   185→---
   186→
   187→# 6. NAVIGATION PSYCHOLOGY
   188→
   189→Preserve the existing single-shell structure:
   190→
   191→```text
   192→page.tsx
   193→   ↓
   194→Zustand currentView
   195→   ↓
   196→ELASTICO views
   197→```
   198→
   199→Do not convert it into route-per-page architecture as part of this redesign.
   200→
   201→The navigation should feel like an analytical workspace, not an administration menu.
   202→
   203→The user should think:
   204→
   205→> I want to see what is happening.
   206→
   207→Then:
   208→
   209→> I want to understand this match.
   210→
   211→Then:
   212→
   213→> I want to understand this player.
   214→
   215→Then:
   216→
   217→> I want to investigate a prediction.
   218→
   219→Group and order navigation according to the user's mental model, not according to the order in which components happened to be written.
   220→

   222→
   223→# 7. THE DASHBOARD IS A COMMAND CENTER
   224→
   225→The dashboard answers:
   226→
   227→> **What matters right now?**
   228→
   229→Prioritize:
   230→
   231→1. Live football
   232→2. Upcoming matches
   233→3. Important current intelligence
   234→4. Current model/prediction information
   235→5. Recent results/performance
   236→6. Deeper analysis
   237→
   238→Do not summarize every database table.
   239→
   240→A useful conceptual composition:
   241→
   242→```text
   243→┌───────────────────────────────────────────────────────────────┐
   244→│ ELASTICO     Dashboard                         Time / Status │
   245→├───────────┬───────────────────────────────────────────────────┤
   246→│           │ CURRENT FOOTBALL STATE                            │
   247→│           ├───────────────────────────────────────────────────┤
   248→│ NAV       │ LIVE / UPCOMING MATCHES                           │
   249→│           ├───────────────────────────┬───────────────────────┤
   250→│           │ PRIMARY ANALYTICAL AREA   │ MODEL / INSIGHT       │
   251→│           ├───────────────────────────┴───────────────────────┤
   252→│           │ SUPPORTING ANALYTICS                              │
   253→│           ├──────────────────────┬────────────────────────────┤
   254→│           │ PLAYERS / TRENDS     │ TABLE / RECENT ACTIVITY   │
   255→└───────────┴──────────────────────┴────────────────────────────┘
   256→```
   257→
   258→This is a composition principle, not a requirement to literally draw these boxes.
   259→
   260→---
   261→
   262→# 8. STOP MAKING EVERYTHING A CARD
   263→
   264→Use a card only when a boundary improves comprehension.
   265→
   266→Sometimes a divider is enough.
   267→
   268→Sometimes whitespace is enough.
   269→
   270→Sometimes several analytical elements should belong to one continuous surface.
   271→
   272→Avoid:
   273→
   274→```text
   275→CARD
   276→CARD
   277→CARD
   278→CARD
   279→CARD
   280→```
   281→
   282→Prefer:
   283→
   284→```text
   285→ANALYTICAL SURFACE
   286→   ├── primary evidence
   287→   ├── supporting evidence
   288→   └── contextual evidence
   289→```
   290→
   291→The product should feel spatially composed rather than assembled from components.
   292→
   293→---
   294→
   295→# 9. SPATIAL DESIGN LANGUAGE
   296→
   297→Use architectural principles:
   298→
   299→- flow
   300→- continuity
   301→- movement
   302→- asymmetry
   303→- geometry
   304→- proportion
   305→- negative space
   306→- layering
   307→- rhythm
   308→- controlled tension
   309→
   310→Do not literally copy an architect's style.
   311→
   312→A large analytical surface can anchor a page.
   313→
   314→A narrow model panel can sit beside it.
   315→
   316→A lower evidence strip can span the workspace.
   317→
   318→A player list can be compact.
   319→
   320→The page should have rhythm rather than a perfectly symmetrical grid.
   321→
   322→Never sacrifice usability for asymmetry.
   323→
   324→---
   325→
   326→# 10. NEGATIVE SPACE
   327→
   328→Do not fill every pixel.
   329→
   330→Spacing communicates hierarchy:
   331→
   332→- large gap = new conceptual section
   333→- medium gap = related group
   334→- small gap = tightly related information
   335→
   336→Do not use identical spacing everywhere.
   337→
   338→---
   339→
   340→# 11. TYPOGRAPHY
   341→
   342→Typography should establish hierarchy without shouting.
   343→
   344→Use:
   345→
   346→- restrained headings
   347→- readable body text
   348→- compact analytical labels
   349→- highly legible numbers
   350→- tabular/monospaced treatment where useful for data
   351→- restrained uppercase labels
   352→
   353→Do not make everything bold.
   354→
   355→Do not make every heading enormous.
   356→
   357→Numbers are important because ELASTICO is analytical.
   358→
   359→---
   360→
   361→# 12. COLOR
   362→
   363→Use a restrained premium dark foundation.
   364→
   365→Color should primarily communicate:
   366→
   367→- state
   368→- hierarchy
   369→- selection
   370→- positive/negative movement
   371→- team identity
   372→- model confidence
   373→- live status
   374→
   375→Do not use neon everywhere.
   376→
   377→Do not make every border glow.
   378→
   379→If everything is highlighted, nothing is highlighted.
   380→
   381→---
   382→
   383→# 13. LIVE / CURRENT / HISTORICAL
   384→
   385→ELASTICO has both memory and a present.
   386→
   387→Make these visually distinct:
   388→
   389→### LIVE
   390→Happening now.
   391→
   392→### UPCOMING
   393→Scheduled.
   394→
   395→### RECENT
   396→Recently completed.
   397→
   398→### HISTORICAL
   399→Past context.
   400→
   401→Completed World Cup data can remain valuable historical data.
   402→
   403→It must never silently become today's football.
   404→
   405→---
   406→
   407→# 14. CHARTS MUST ANSWER QUESTIONS
   408→
   409→Never add a chart merely because analytics products have charts.
   410→
   411→Every visualization must answer a question.
   412→
   413→Bad:
   414→
   415→> Performance
   416→
   417→with a random line.
   418→
   419→Good:
   420→
   421→> Chance Creation
   422→
   423→showing meaningful xG/shot-quality information.
   424→
   425→Good:
   426→
   427→> Spatial Dominance
   428→
   429→only when genuine spatial data exists.
   430→
   431→Good:
   432→
   433→> Why did the model move?
   434→
   435→only if real model-history data exists.
   436→
   437→A visualization without a question is decoration.
   438→
   439→---
   440→
   441→# 15. DATA VISUALIZATION
   442→
   443→Prefer:
   444→
   445→- direct labels
   446→- useful annotations
   447→- restrained grids
   448→- clear axes
   449→- contextual legends
   450→- meaningful hover states
   451→- comparisons
   452→- changes over time
   453→
   454→Avoid:
   455→
   456→- decorative 3D charts
   457→- meaningless gauges
   458→- unnecessary rings
   459→- excessive chart chrome
   460→- charts where colors are the only distinction
   461→
   462→The visualization must help the analyst think.
   463→

   465→

   470→> AI INSIGHT

   490→Do not invent explainability when the underlying engine cannot support it.

   493→
   494→# 17. UNCERTAINTY IS A FEATURE
   495→
   496→A serious intelligence product does not pretend to know everything.
   497→
   498→If data is unavailable:
   499→
   500→> Data unavailable for this match.
   501→
   502→If spatial data is unavailable:
   503→
   504→> Spatial data not available for this match.
   505→
   506→If there is no prediction:
   507→
   508→> No prediction yet.
   509→
   510→If the provider is stale:
   511→
   512→> Data delayed.
   513→
   514→Design these states beautifully.
   515→
   516→Never fill missing information with fake numbers.

   519→
   520→# 18. REAL ASSETS ARE PART OF THE DESIGN
   521→
   522→This is non-negotiable.
   523→
   524→Do not use generic circles where real assets exist.
   525→
   526→Use legitimate real assets for:
   527→
   528→- team crests
   529→- player headshots
   530→- country flags
   531→- competition logos
   532→- news imagery where appropriate
   533→
   534→Build an asset-resolution layer instead of hardcoding image URLs inside components.
   535→
   536→Conceptually:
   537→
   538→```text
   539→Entity
   540→   ↓
   541→Verified provider image
   542→   ↓
   543→Local cached asset where licensing permits
   544→   ↓
   545→Professional fallback
   546→```
   547→
   548→Prefer:
   549→
   550→- assets already supplied by ELASTICO's real data providers
   551→- properly licensed/open-source assets
   552→- maintained local assets where licensing permits
   553→- established flag libraries for country flags
   554→
   555→Do not scrape arbitrary copyrighted images merely because a search engine can find them.
   556→
   557→Do not use AI-generated faces to represent real players.
   558→
   559→If no legitimate image exists, use:
   560→
   561→- initials
   562→- verified crest
   563→- neutral silhouette
   564→- competition mark
   565→- verified flag where nationality is known
   566→
   567→A professional fallback is better than a fake photograph.
   568→
